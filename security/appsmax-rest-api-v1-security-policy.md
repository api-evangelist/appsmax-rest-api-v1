# Безопасность

## API-токены

- храните токен только на сервере в secret-хранилище;
- выдавайте минимально необходимые scopes;
- не помещайте токен в репозиторий, браузерный код, мобильное приложение, URL,
  скриншот или обычное письмо;
- отзовите токен и создайте новый при подозрении на раскрытие;
- не публикуйте рабочие payload, если в них есть персональные данные.

## Сообщение об уязвимости

Не публикуйте действующую уязвимость и данные затронутых пользователей в issue.
Передайте краткое описание через официальный контакт:
<https://appsmax.ru/contacts/>.

В первом сообщении достаточно указать затронутый компонент, ожидаемое и
фактическое поведение и безопасные шаги воспроизведения. Не прикладывайте
API-токены, пароли, персональные данные и production-выгрузки.

## Область репозитория

Этот репозиторий содержит публичную reference, а не исходный код AppsMax.
Ошибки документации можно обсуждать публично, если сообщение не раскрывает
секреты, персональные данные или способ эксплуатации действующей уязвимости.
